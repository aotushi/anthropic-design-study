# 08 应用指南

[返回总览](../README.md) · [查看方法与证据](07-methodology-and-sources.md)

## 先学习职责，再选择外观

可以先从信息分工建立自己的页面：标题负责建立主题，正文解释价值，目录帮助定位，控件推动行动，代码和示例帮助执行。再根据内容与品牌选择颜色、字体和装饰。

## 为不同任务选取适合的组合

| 你的页面 | 值得借鉴的组合 | 需要自己重新决定的部分 |
|---|---|---|
| 公司或品牌介绍 | 清晰的主张、少量重点内容、宽松编排 | 叙事语气、图片风格、真正的差异化信息 |
| 产品介绍 | 明确标题、场景演示、层次清楚的主要动作 | 演示的可信度、登录前后路径、购买或试用门槛 |
| 内容资源库 | 分类导航、搜索、主题标签、阅读时间 | 分类是否符合读者寻找内容的方式 |
| 技术文档 | 导航树、正文、页内目录、代码复制、步骤 | 内容版本、示例可运行性、报错和迁移说明 |
| 课程 | 学习目标、课时信息、视频与文字、下一步 | 练习质量、学习进度、完成条件、无视频替代 |
| 开发者博客 | 精简的文章行、日期与分类、技术性标签 | 是否需要复古装饰，以及装饰是否影响可读性 |

## 建立自己的字体分工

先确定三种角色，再决定是否真的需要三种字体：

1. **展示与标题。** 需要辨识度，但必须能够支持真实标题长度和目标语言。
2. **阅读与操作。** 正文、导航和按钮优先考虑清晰、稳定和多语言支持。
3. **代码与结构化信息。** 等宽字体适用于代码、命令或需要对齐的内容，不必铺满所有正文。

选择字体时，同时确认授权、加载成本和语言覆盖。本文涉及的素材范围见[素材说明](../NOTICE.md)。

中文标题应使用真实内容确定字号：先检查字数与字面密度，再调整换行、行高和窄屏宽度，使标题的视觉分量与正文相协调。

## 让颜色表达层级

以少量背景层级组织页面，以高对比文字承载主要内容，再为强调、状态和代码语法分别分配角色。链接、警告、装饰与选中状态各有含义，配色应让这些含义容易区分。

从浅色背景起步时，将正文、次级文字、细边框和控件一起检查，并覆盖悬停、焦点和禁用状态。

## 密度由任务决定

营销页面可以让一个重点占据较大区域；知识页面需要让读者持续看到当前位置和下一步；操作密集的后台需要为并列信息和频繁操作保留空间。布局密度应与任务复杂度相匹配。

建议先画出读者的任务顺序，再分配空间：

| 任务 | 需要最先出现的信息 | 值得保留的辅助信息 |
|---|---|---|
| 了解产品 | 产品做什么、适合谁 | 一两个可信示例 |
| 判断方案 | 价格与适用范围 | 功能差异、限制说明 |
| 完成安装 | 前提和步骤 | 平台切换、故障排查 |
| 学习概念 | 学习目标与核心解释 | 例子、练习、下一课 |
| 解决问题 | 搜索和问题分类 | 相关问题、返回路径 |

## 从研究到落地的检查顺序

- **内容：** 标题能否准确表达页面目的，正文是否解释了必要条件。
- **结构：** 主导航、分类和页内目录是否各司其职。
- **视觉：** 字体、间距、边框与颜色是否形成可解释的层级。
- **交互：** 搜索、切换和展开后是否有清晰状态反馈，返回是否自然。
- **窄屏：** 内容顺序是否合理，长标题和代码是否挤压页面。
- **可访问性：** 键盘能否完成关键流程，焦点是否可见，文字与控件是否清楚。
- **可靠性：** 字体、图片或视频未加载时，内容是否仍能理解和使用。

完成初稿后，用真实内容走完关键任务，再检查视觉层级、导航与状态反馈是否支持每一步。
